# Agent Note: MCP 市场成员授权

[English](2026-10-31-mcp-market-member-authorization.md) | 中文

Status: implemented

## Problem

MCP 市场目录和执行接口必须对应已认证企微成员。浏览器传入的身份、共享目录或发布者凭据都可能让一个成员看到或执行另一个成员的 MCP。

## Decision

Host 从已验证的公司 Principal 或 Session 持久化所有者解析 `CompanyMarketSubject`。浏览器 Remote 不接收 subject 字段。MCP Provider 使用市场已有的 HR 只读接口，将官方企微 id 映射为门户账号，或将门户账号映射为企微 id，要求身份精确匹配。已有列表负责上架和可见范围，已有权限检查按解析后的企微身份判定使用权。

DSH 读取既有权限，不保存启用偏好，也不提供申请或授权操作。身份解析或刷新失败会清空目录。工具 schema 只在显式发现时加载，网关 schema 失败不会隐藏成员目录。实际 MCP 调用暂缓，在发送调用请求前即失败；目录访问权不是传输凭据。

## Alternatives considered

共享网关目录实现更简单，但后端请求没有已验证身份时无法区分成员。读取公开 MCP endpoint 配置会暴露创建者专属数据，也不能证明使用授权。从 Remote 参数传入 `sub` 被拒绝，因为调用者可以选择其他身份。

新增成员目录与执行接口并使用服务 Token 可以集中处理，但所给市场文档没有这些接口及凭据，因此适配器复用已有只读接口。把企微 id 当作门户用户 id 可以省去查询，却会混用不同身份范围并选错账号。仅使用权限检查也不可取，因为它没有检查上架状态。

## Consequences

适配器要求唯一的在职 HR 与门户映射，以及到已有后端只读接口的可信内部访问。公网门户网关认证和 MCP 执行仍需另行接入。本地 fixture 验证成员隔离、身份精确映射、已上架候选查询和权限变更，尚未验证生产连通性。
