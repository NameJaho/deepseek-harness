# Agent Note: 企业私有源码部署

Status: implemented

[English](2026-10-31-private-company-source-deployment.md) | 中文

## 问题

企业集成为私有部署配置，而常规包目录规则默认所有包都参与公开 npm 发布。为了满足该默认规则而移除 `private`，会在没有部署需求的情况下使企业包具备公开发布资格。

## 决定

Workspace 约束显式列出六个现有企业包作为私有部署成员。它们必须保留 `private: true` 并省略 `publishConfig`。共享版本、依赖规则、编译器分面、导出与打包内容检查仍然适用。发布发现流程已经依照[发布序列规则](2026-08-10-npm-release-sequences.zh.md)排除私有 manifest；该规则保持有效，本决定未取代它。

部署使用源码 CLI 和配置 patch。公开 npm CLI 发布流程不作为本企业分支的分发方式。公开分发需要单独审核企业依赖的交付方式，不能只修改私有标记。

没有运行时值的企业 `/types` 入口只暴露声明。它们不发布编译器输出的未打包浏览器模块，因为其中的样式导入需要客户端打包器处理。运行时客户端入口仍为打包后的 `/client` 模块。共享 Host 提供方的运行时导入归类为必须使用 peer；不增加重复安装安全豁免。

## 考虑过的替代方案

**把企业包作为普通发布成员公开发布。** 这符合公开目录的默认规则，但源码部署无需公开发布，也不应让私有集成具备进入公开 registry 的资格。

**让整个企业目录不再接受校验。** 这省去了显式维护成员清单的工作，但会默许新私有包加入，并丢失有用的版本与产物检查。新增集成必须显式分类。

## 影响

企业部署使用源码 checkout、冻结的 workspace lockfile 和常规产物构建。约束回归测试拒绝公开标记、发布配置、过期版本和缺少的打包内容。该限定范围的例外不改变其他发布成员，也不移除发布发现流程跳过私有包的规则。
